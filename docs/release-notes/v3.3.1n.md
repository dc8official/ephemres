# Release Notes: Ephemres v3.3.1n

**Release Tag**: `v3.3.1n`  
**Target Architecture**: Full Rebranding & Architectural Path Migration  
**Release Date**: October 2026  
**Repository**: `https://github.com/dc8official/ephemres.git`  

---

## Executive Summary

Ephemres `v3.3.1n` completes the comprehensive rebranding and filesystem reorganization of the platform from LNMP/netmon to **Ephemres**. This release establishes a unified root directory structure at `/opt/ephemres`, streamlines systemd service naming (`ephemres-api`, `ephemres-engine`, `ephemres-flowd`), updates all environment variable schemas to `EPHEMRES_` while maintaining 100% backward compatibility with `NETMON_` configurations, derivations, and restores, and realigns all frontend and backend UI assets.

Branches `v3.3.0` and `v3.1.35s` are frozen as legacy release snapshots. All active developments continue on the `v3.3.1n` release line.

---

## What's Changed in v3.3.1n

### 1. Unified Directory Layout & Host Path Flattening
* **Flattened Repository Root**: Replaced legacy `/opt/netmon/noop` and separate `/opt/netmon/venv` paths with a single canonical tree at `/opt/ephemres`.
* **Integrated Virtualenv**: The production virtual environment now resides at `/opt/ephemres/venv`, explicitly ignored by `.gitignore` to prevent polluting `git status`.
* **Standardized Log Directory**: All operational log streams are written directly to `/var/log/ephemres/` with automated logrotate profiles.
* **Standardized Configuration Paths**: Production configurations reside at `/etc/ephemres/config.toml` and `/etc/ephemres/ephemres.env` (with automatic fallback to `/etc/netmon/` if present).

### 2. Systemd Service Realignment & Privilege Isolation
* **Renamed Service Units**:
  * `netmon-api.service` ➔ `ephemres-api.service`
  * `netmon-engine.service` ➔ `ephemres-engine.service`
  * `netmon-flowd.service` ➔ `ephemres-flowd.service`
* **Dedicated System Identity**: Daemons execute under the unprivileged system user and group `ephemres:ephemres`.
* **Targeted Capabilities**: Raw socket operations (`CAP_NET_RAW`) are granted strictly to `$(readlink -f /opt/ephemres/venv/bin/python3)`.
* **Reverse Proxy Alignment**: Nginx upstream proxy definitions, static frontend alias paths (`/opt/ephemres/frontend/dist`), and access/error logs are updated to `ephemres`.

### 3. Dual-Layer Configuration & Environment Parity
* **Environment Prefix**: Configuration loader supports `EPHEMRES_` environment variables (`EPHEMRES_DB_PASSWORD`, `EPHEMRES_SECRET_KEY`, `EPHEMRES_JWT_SECRET`, etc.) with transparent fallback to `NETMON_` equivalents.
* **Database Compatibility**: Preserved default PostgreSQL database name `netmon` and user `netmon_user` to ensure zero disruption and seamless restoration of TimescaleDB backups from `v3.3.0`.
* **Dual-Key Cryptographic Decryption**: HKDF key derivation defaults to `ephemres-alert-crypto-salt-v1` for new secret encryption while gracefully falling back to legacy `lnmp-alert-crypto-salt-v1` when decrypting historical database secrets.

### 4. Application Branding & UI Realignment
* **FastAPI Title & Endpoints**: API title updated to `Ephemres - Network Monitoring Platform`, version string bumped to `3.3.1n`, and status endpoints `/api/v1/version` and `/api/v1/health` report `3.3.1n`.
* **Frontend Package & Title**: `frontend/package.json` package name updated to `ephemres-frontend` version `3.3.1n`; `<title>` updated to `Ephemres v3.3.1n — Network Monitoring Platform`.
* **Navigation & Presentation**: Header branding, login interface, topology engine labels, PDF document metadata, alert formatters (Teams, Slack, Discord, Email), and telemetry CSV export filenames aligned to **Ephemres**.

## Upgrade & Migration Guide

Upgrading an existing `v3.3.0` installation to `v3.3.1n` is automated by `deploy/upgrade.sh`:

```bash
cd /opt/ephemres
sudo ./deploy/upgrade.sh
```

The upgrade script automatically:
1. Migrates legacy configuration from `/etc/netmon/` to `/etc/ephemres/`.
2. Creates the `ephemres:ephemres` system user and group.
3. Deactivates and replaces old `netmon-*` systemd units with `ephemres-*`.
4. Updates virtual environment packages and assigns `CAP_NET_RAW`.
5. Runs schema migrations and restarts all services.
