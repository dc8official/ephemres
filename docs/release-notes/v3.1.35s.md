**Release Date**: September 2026  
**Track**: Enterprise Long-Term Support (LTS Maintenance Line)  
**Baseline**: Consolidated from `v3.1.28s` (Historical tag `v3.1.28s`)

## Executive Summary

LNMP `v3.1.35s` serves as the official enterprise Long-Term Support (LTS) release line. It consolidates the stability baseline of `v3.1.28s` and incorporates **6 critical operational and security hotfixes** without introducing breaking API changes, frontend churn, or database migration overhead.

Monitored fleets running on `v3.1.35s` benefit from 100% mathematical accuracy in SLA reporting, hardened SSRF socket isolation, secure Server-Sent Event streaming, and TimescaleDB hypertable decompression safety.

---

## Key Hotfixes Included

### 1. BUG-01 (DAT-01): Clamped SLA Uptime Duration Calculation
- **Files**: `backend/app/repositories/endpoint_repo.py`, `backend/app/routers/endpoints.py`
- **Impact**: Resolved an issue where endpoints with active events spanning multiple days produced inaccurate (e.g., 0.07% or 0.00%) uptime percentages.
- **Remediation**: The repository query now calculates window-clamped durations in SQL using:
  ```sql
  clamped_start = GREATEST(start_time, :since_utc)
  clamped_end = LEAST(COALESCE(end_time, :now_utc), :now_utc)
  duration_seconds = GREATEST(0, EXTRACT(EPOCH FROM (clamped_end - clamped_start)))
  ```
  Passing `uptime_seconds` directly to `calculate_uptime_denominator_and_percentage()` accurately calculates 100.00% uptime for continuously healthy endpoints.

### 2. BUG-01b: SLA Parity Fix (Boundary-Overlapping Window Queries)
- **Files**: `backend/app/repositories/report_repo.py`, `backend/app/routers/reports.py`
- **Impact**: Resolved an SLA parity discrepancy between Dashboard Cards and Endpoint Detailed Views where endpoints open for >24 hours reported `0.00%` in the detailed view due to `start_time >= start_dt` filtering dropping earlier open events.
- **Remediation**: Updated `ReportRepository.get_uptime_events()` to query boundary-overlapping events (`start_time <= end_dt AND (end_time IS NULL OR end_time >= start_dt)`), and clamped event intervals strictly between `start_dt` and `end_dt` in `reports.py`, guaranteeing 100% mathematical parity.

### 3. BUG-02 (FE-01): SSE Topology Map Parsing Fix
- **Files**: `frontend/src/components/TopologyMap.vue`
- **Impact**: Fixed an unhandled `ReferenceError: payload is not defined` in `initSSE()` that broke dynamic node recoloring when receiving real-time Server-Sent Events.
- **Remediation**: Correctly parsed the incoming event data (`const payload = JSON.parse(event.data)`) within the handler try-block, restoring smooth real-time visual updates.

### 4. BUG-03 (SEC-01): SSE Endpoint Authentication Enforcement
- **Files**: `backend/app/routers/events.py`, `frontend/src/composables/useSSE.js`
- **Impact**: The real-time telemetry stream at `GET /api/v1/events/stream` previously lacked authentication dependencies, allowing unauthorized access to live telemetry envelopes.
- **Remediation**: Added `current_user: dict = Depends(get_current_user)` authentication dependency to `/api/v1/events/stream` and configured `EventSource` with `{ withCredentials: true }` in `useSSE.js`.

### 5. BUG-04 (SEC-02): SSRF-Safe Synthetic HTTP Probing
- **Files**: `monitoring/synthetic.py`
- **Impact**: Synthetic HTTP/HTTPS probers could be coerced into following redirects to prohibited cloud metadata services or loopback interfaces.
- **Remediation**: Integrated `create_ssrf_safe_client(timeout=timeout, allow_private=True)` with zero-trust socket DNS pinning and disabled automatic redirect following (`follow_redirects=False`). Updated probe User-Agent string to `LNMP-SyntheticProbe/3.1.35s (+https://github.com/dc8official/lnmp)`.

### 6. STAB-01 (DAT-02): 24-Hour Continuous Event Duration Rollover
- **Files**: `monitoring/state_machine.py`
- **Impact**: Stable endpoints in an unchanged state continuously for >7 days caused in-place `UPDATE` queries to target read-only TimescaleDB compressed chunks, raising database errors and terminating the state machine coroutine.
- **Remediation**: Implemented an automated 24-hour event duration rollover in `StateMachine.step()`. When an active event reaches 86,400 seconds, it is closed gracefully and a new continuous open event is inserted with `is_split_event = true`, preventing updates from ever hitting compressed hypertable chunks.

### 7. BUG-06 (OPS-02): Logrotate Daemon File Descriptor Leak Prevention
- **Files**: `deploy/logrotate.conf`
- **Impact**: When the host logrotate utility rotated `/var/log/netmon/*.log`, Python's `RotatingFileHandler` retained open file descriptors pointing to deleted inodes, leading to silent logging failures or disk space leaks.
- **Remediation**: Added the `copytruncate` directive to `deploy/logrotate.conf`, allowing logrotate to truncate in place without breaking Python file handles.

## Upgrade Instructions

From an existing LNMP installation:
```bash
cd ~/lnmp
git fetch --all --tags
git checkout v3.1.35s
sudo ./deploy/upgrade.sh
```

To verify the running version after upgrade:
```bash
curl -s http://127.0.0.1:8000/api/v1/version | jq .
```
Expected output:
```json
{
  "version": "3.1.35s"
}
```
