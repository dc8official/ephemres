# Ephemres Changelog & Evolutionary Architecture

All notable technical changes, architectural upgrades, security enhancements, and operational milestones for Ephemres are documented in this file.

The versioning format follows [Semantic Versioning](https://semver.org/).

## [Version 3.3.6] — Unreleased (branch `v3.3.6`)
### 🔐 Per-Account Sessions

| Upgrade Domain | Technical Implementation | Operational & Performance Benefit |
| :--- | :--- | :--- |
| **Idle Timeout per Account (`0022`)** | `users.session_idle_minutes` (admin 15/30/60 min, default 30; viewer 30 min/1/2/4 h, default 2 h) and `user_sessions.last_activity_at`. The browser reports clicks, key presses and navigation through the new `POST /auth/activity` at most once a minute (`composables/useActivityTracker.js`); polling and the live-event stream don't count. The session check reads the account's timeout on every request (`services/session_policy.py`, `PostgresSessionStore`). | Nobody is signed out mid-click any more, and an unattended screen still times out. A changed timeout applies to open sessions at once. |
| **Admin 12-Hour Cap** | Admin sessions end 12 hours after sign-in whatever the activity. Tokens and cookies last until the absolute end plus one hour (viewers: a 7-day backstop plus one hour); the session row decides. | Limits how long an admin session left open on a shared machine stays usable. |
| **Session Limit per Account** | `users.max_sessions` (1–10) replaces the single `[security] max_active_sessions_per_user`, which now only seeds new accounts and the upgrade. Timed-out sessions are swept at each sign-in so they never count against the limit. | Different accounts can have different limits. |
| **Why a Session Ended (`ended_sessions`)** | Every ended session is recorded with a reason (`idle_timeout`, `absolute_timeout`, `signed_in_elsewhere`, `signed_out`, `password_changed`, `ended_by_admin`, kept 8 days). A refused request answers `401` with `X-Session-End-Reason` (and `X-Session-Idle-Minutes`), and the sign-in page explains it. | "You were signed out because this account signed in on another device" instead of an unexplained return to the sign-in page. |
| **Users Tab and Settings** | Users table gains a Session column and an Edit dialog (role, timeout, session limit); Add User takes both values. `GET /users/session-options` serves the choices. The global "User Session Timeout" control and the fixed "Max Concurrent Traces" text are removed from Security & Discovery; `session_timeout` is still accepted by `PATCH /settings`. | Session rules are set where the accounts are. |
| **Active Sessions List** | The Users table's "1 of 2 sessions" count opens the account's live sessions (device from the browser string, address, sign-in time, last activity, when it ends if left alone), with End per session and End all (`GET`/`DELETE /users/{id}/sessions[/{session_id}]`, audited). `user_sessions.client_ip` and `user_agent` are recorded at sign-in. | Find a shared login still open on another screen and close it, without resetting the password. |
| **Upgrade and Restore** | Migration `0022` sets admins to 30 minutes and viewers to the old `session_timeout` (else the config value, else 120) fitted down to a viewer choice, and the session limit from the config. A restore of an older backup gives each account its role's default. Open sessions survive the upgrade. | Upgrading from v3.2.0, v3.3.0 or v3.3.5 signs nobody out and shortens no viewer's sign-in by surprise. |

| Upgrade Domain | Technical Implementation | Operational & Performance Benefit |
| :--- | :--- | :--- |

The old free-text `location` is kept as the location within a site. Autocomplete from `GET /endpoints/suggestions`; a value typed in another case takes the spelling in use; tags are lower case. | Group endpoints by branch site, building and role without a managed site table; nothing is required. |

Used by `GET /endpoints`, `GET /endpoints/match`, the fleet summary, the PDF and the CSV export. | The same filter gives the same endpoints on every page and in every report. |

Dashboard tiles count the filtered endpoints with a whole-fleet figure underneath. | A branch's view can be bookmarked, shared and followed from page to page. |
| **Reports by Filter** | Fleet summary, PDF and CSV accept the filter (or a hand-picked list, or both). The PDF prints the filter and that sites and tags are as assigned at generation. | One branch's SLA report without picking its devices by hand. |
| **Topology Map Filter with Dim / Hide** | The map shows matching endpoints and the path to them; other devices on the path are faded (Dim) or, for endpoints, left out with the path joined by a dashed line (Hide). | Kenneth can compare both on real data before one is chosen. |
| **Bulk Assign and Rename** | Dashboard selection gains Set site, Set location, Add tag, Remove tag and Select all matching (`POST /endpoints/bulk-update`); Settings → Organization renames or merges values (`POST /endpoints/rename`). ### 🛰️ Topology: Faster Route Rediscovery and a Failover-Aware Baseline

| Upgrade Domain | Technical Implementation | Operational & Performance Benefit |
| :--- | :--- | :--- |
| **Current and Normal Path (`0024`)** | `endpoint_baseline_routes.hops` is now the current path; `normal_hops` / `normal_since` / `normal_pinned` hold the normal one. Every trace goes through `services/route_paths.record_trace`: a different path counts after two traces ≥ 2 minutes apart agree; a path held 24 h becomes normal unless pinned. Before, every trace (nightly, recovery, flow hint) overwrote the single baseline. | A failover path no longer becomes "normal" silently, and a flapping link no longer rewrites the baseline on each trace. |
| **RCA Against the Path in Use** | Root-cause analysis compares a failure with the current path and adds "On an alternate path since … (normal path via …)" when it was off the normal one. | The blamed hop is on the path traffic was really using. |
| **Route-Change Log** | `endpoint_route_changes`: path changed, back to normal, became normal, pinned, flapping; with the trigger and the first differing hop. At most one entry per endpoint per 15 min; 4+ changes in an hour log one "flapping" entry. Shown in the new Route panel on the endpoint page, with Make normal / Pin / Unpin for admins (`GET /endpoints/{id}/route`, `POST …/route/normal`, `DELETE …/route/pin`). | "14:02: abj-sw left PE-A, now via ISP-B" without digging through traces. |
| **New Triggers** | Transit: when a monitored device that others route through goes DOWN, the endpoints behind it still UP a cycle later are re-traced; when it comes back, those off their normal path through it are. Reply TTL: the engine reads the TTL of raw IPv4 ping replies and publishes a `ROUTE_HINT` (`reason: ttl`) when it changes and holds 3 cycles (`monitoring/ttl_watch.py`). | Route changes are seen within minutes, not at midnight. |
| **Parallel Discovery and Rolling Schedule** | `discovery_parallel` (1–8, default 2) traces at once, traces through the same router taking turns; the diagnostics trace limit is that plus 2 for incident/RCA traces (was a fixed 3). `rediscovery_hours` (6/12/24, default 24) re-traces each endpoint on a spread-out schedule in place of the midnight run. Both in Settings → Discovery & topology. | Faster full rediscovery without router reply limits leaving `* * *` holes, and no midnight burst. |
| **Map Follows Route Changes on Every Worker** | Route changes are published through the event broker; each API worker rebuilds its map (debounced) and tells its browsers. The map draws the unused part of a normal path faded and dashed and labels the endpoint "⤳ alternate path since …". | Before, only the worker that ran a trace updated its map. |

### 📊 Traffic Page Rebuilt: Each WAN Link Now, and Usual

From the review in `docs/architecture/traffic-page-review-2026-11-13.md`. No migration.

| Upgrade Domain | Technical Implementation | Operational & Performance Benefit |
| :--- | :--- | :--- |
| **Counted Once Everywhere** | Applications, QoS, traffic zones, the overview's directions and the "All flows" chart count each conversation once per bucket at the largest router report, like Conversations (`conversations.counted_once_cte`, one GROUPING SETS pass shared with the PDF). Up to 2 hours from minutes, beyond from the hourly conversation tier. | Traffic between two sites, which both routers export, no longer counts twice in Applications and Zones; their totals now equal Conversations'. |
| **One Meaning of "Internal"** | A private address (RFC 1918, loopback, link-local, IPv6 ULA; a fixed list, mirrored in SQL) or a monitored endpoint, for zones, the overview and the chart, which now split four ways: inbound, outbound, internal, transit. | Users' PCs are no longer "transit" because they aren't endpoints. |
| **Bulk, Port Names, Less Noise** | Bulk = full-size packets, seen 30 min or more at 5 Mb/s or more while seen; large packets otherwise are "Download". One port-name table for the page and the PDF (UDP 443 "QUIC (HTTP/3)", 1433 MS SQL, 8801 Zoom, 873 rsync, 23 Telnet…). Whole packets per flow; TCP flags only on suspicious rows; zones at 0% hidden; the QoS badge counts marked classes only. | The Bulk filter finds the backup job, not every Microsoft 365 download. |
| **Filter and Device Picker** | Every `/bandwidth/*` read takes the shared filter (site, location, tags, type, search) and `device_id` (`exporter_id` still accepted); they resolve to the routers in scope. The picker is grouped by site and lists SNMP-only routers. Unregistered flow sources are one line with Review, Enroll and Link. | "Show me Abuja" works on the Traffic page as on the dashboard and reports. |
| **Now: Each WAN Link Against Its Capacity** | New `GET /bandwidth/wan-links` (`services/wan_links.py`): per link, the last five minutes (SNMP else flows), speed and its source, the usual range for this hour, today's peak, SNMP state and open traffic alerts. On the page, above every tab: In and Out capacity bars with the usual range and today's peak, "In 25% above usual", **Set speed** for a link without one, and a status line that turns amber when a router stops sending flows. The KPI tile row and the WAN share table are gone. | The first thing on the page answers "how full is each link, and is that normal?" |
| **Usual Range** | `services/traffic_usual.py`: per link and direction, from the last 28 days of hourly averages in the server's timezone (named zone, so summer time is followed); weekday/weekend under 21 days of history, day of week from 21; a range from 3 samples, trimmed from 5. "Above usual" from more than 10% over its top. Computed per request in one query. | A busy Monday morning is compared with Monday mornings. |
| **One Chart per WAN Link** | `?series=1` on the same route adds per-link series (minutes up to 6h, hours beyond with each hour's busiest minute), the usual range per bucket and SNMP down spans. Charts in % of capacity with a 100% line, grouped by site; trouble and the busiest open first (6 at most), the rest one sparkline row each. "All links together" keeps the combined chart. | A full link, an outage and a link above its usual range are visible without hovering. |
| **Interfaces Across Devices** | `GET /bandwidth/interfaces` without a device lists every router's interfaces in scope (`services/interface_table.py`): WAN first by utilisation, then by traffic, shut-down ports last; Now in/out beside the window's avg / P95 / peak; status from SNMP (up, down, shut down, not answering) with down time in the window ("down 40 min, Thu 14:00"). Sortable table; a row opens its router with the interface isolated. | No more "pick a device first" to find the busiest or broken interface. |
| **Faster Interface Reads** | `interface_traffic.minute_source` / `hourly_source` (SNMP else flow) are one GROUP BY instead of an anti-join PostgreSQL planned as a merge comparing every flow minute with every SNMP minute of the interface: one router over 7 days went from 17-24 s (past the API's 10 s limit) to about 0.1 s. Every interface figure uses them. | No time-outs on one router's interfaces over a week. |
| **Conversations: Where and When** | Conversation rows carry `routers` (each with its site, and its WAN link when the router has only one: flows are stored per router, not per interface) and `first_seen` / `last_seen` (to the minute up to 2 hours, to the hour beyond). The table gains a Site column with the routers on hover; the Security table adds first / last seen and the router with its link. Security tiles follow the window (new `GET /bandwidth/anomalies`). | "52.97.146.2 → 10.1.20.12 is Abuja" without looking it up, and a scan's row says when it ran and where it came in. |

### 🚨 Traffic Alerts on WAN Links

| Upgrade Domain | Technical Implementation | Operational & Performance Benefit |
| :--- | :--- | :--- |
| **Busy-Link Alerts** | `services/traffic_alerts.py`, run by the alert-dispatcher leader at 20 s past each minute on minutes at least 2 minutes old. A WAN link with a speed alerts when inbound or outbound utilisation (from `flow_interface_minute_rollups`) is above the threshold in every minute of the duration (default 80% for 15 min), once per spell; back to normal after 5 minutes 10 points under, with how long and the peak. | "abj-rtr WAN1: inbound traffic above 80% for 15 min" instead of finding out from users. |

The interface editors set Default, Custom or Off per WAN link (`alert` in `flow_interface_aliases`). `traffic_alert_state` keeps open alerts across leader changes. | A link that is always busy can have its own rule or none. |

### 📡 SNMP, Step 1: Core and Device Survey

| Upgrade Domain | Technical Implementation | Operational & Performance Benefit |
| :--- | :--- | :--- |
| **Hand-Written SNMP (`monitoring/snmp/`)** | BER codec, SNMP v2c and v3 (USM: HMAC-MD5/SHA-1/SHA-2, AES-128-CFB, DES-CBC; engine discovery, clock following, reboot resync) and an asyncio client with GET, GETNEXT, GETBULK and multi-column walks that halve repetitions on tooBig and fall back to single columns when a device drops a request. No new dependencies; the OpenSSL binding moved to `core/libcrypto.py`. | The base of the coming SNMP poller, checked against RFC 3414 key vectors and real Cisco and MikroTik devices. |
| **SNMP Poller, Step 1 (`ephemres-snmpd`, `0026`)** | A new always-running service (idle until SNMP is switched on) polls endpoints that have a credential set: status every 30 s to 5 min, interface list on change (`ifTableLastChange`) and every 15 min, full probe on first contact, reboot, request, failures and daily. Shared credential sets (`snmp_credentials`, secrets encrypted and write-only, audited, backed up) with a Test button; `endpoints.snmp_credential_id` set in the endpoint form or in bulk. `snmp_device_state`, `snmp_interfaces`, `snmp_interface_events`. Endpoint page SNMP panel with Probe now. | Interface names, speeds and up/down status come from the device; reboots are noticed. |
| **Neighbours, Map Placement and Link Events (Step 3, `0028`)** | `snmp_neighbours` from LLDP/LLDP-V2/CDP, matched to endpoints by address (including SNMP-reported addresses), MAC, then name; endpoint panel lists them with **Add as endpoint**. The map places endpoints traceroute cannot place from these links (walked out from placed devices; a manual parent wins), marked `via` LLDP/CDP and drawn dotted; RCA names a down LLDP/CDP parent and counts LLDP/CDP children as symptoms. Interface up/down events are claimed once by the alert leader: WAN links send `LINK_DOWN` / `LINK_UP` to channels that tick them, and every link change re-traces the routes through the device (transit trigger, now matching any SNMP-reported address). | Switches appear where they are cabled, incidents point at the right switch, and a WAN link drop pages the team and moves routes on the map within a poll. |
| **Interface Traffic From SNMP Counters (Step 2, `0027`)** | Every poll reads the interface counters with the status (64-bit where answered; errors, discards, discontinuity time) and stores per-minute deltas in `snmp_interface_minute_rollups` (hypertable, 7 days) with an hourly continuous aggregate (365 days). Deltas use the device's uptime clock, are shared across the minutes they span, and are dropped across resets, long gaps or impossible rates; readings survive a restart (`snmp_device_state.counters`). `services/interface_traffic.py` makes interface charts and table, WAN totals and chart, traffic alerts and the PDF read SNMP minutes where present and flow minutes otherwise; an **SNMP** badge marks those interfaces. | Exact interface traffic where devices answer SNMP, even with no flow export; no gap or double count at the switch-over. |
| **Names and Speeds From SNMP** | `services/snmp_inventory.py` merges SNMP under the typed values for the Traffic page, WAN totals, traffic alerts, PDF and route paths: typed name, else `ifAlias`, else `ifName`; typed speed, else `ifHighSpeed`. Editors show SNMP values as greyed defaults and store only typed ones (an interface name is now optional). Typed entries follow renumbered interfaces. | No more typing interface names; a contracted speed still overrides the port speed. |
| **Any-Vendor SNMPv3 and Device Profiles** | AES-192/256 with both key-stretching methods (net-snmp style `aes192`/`aes256`, Cisco style `aes192c`/`aes256c`) and 3DES, checked against the drafts' published keys, NIST vectors and a Cisco agent; one password for both (Meraki, UniFi); SNMPv3 context names; LLDP-V2-MIB fallback; `ifCounterDiscontinuityTime`; GETNEXT fallback when GETBULK goes unanswered. `monitoring/snmp/profile.py` records what each device answers and its quirks, so polls skip what it drops. Based on `docs/architecture/snmp-vendor-research.md`. | Works with whatever SNMPv3 settings a Cisco, Juniper, Aruba, Meraki, UniFi, Sophos, Fortinet or MikroTik device offers, without vendor-specific code. |
| **Device Survey** | `python -m monitoring.snmp.survey <host>` reads system info, interfaces (64-bit counters, speeds, errors, twice to show traffic), IPv4 addresses, LLDP and CDP neighbours, and reports what the device answers, what it did not, and what a read costs. Secrets only from the environment or a prompt; `--json` for the full report. See `docs/snmp-guide.md`. | Shows what Meraki, Sophos and other branch devices really expose before the poller's scope is fixed. |

### 🧰 Upgrades That Land the Release, and Never Leave Monitoring Down

From the v3.3.5 → v3.3.6 upgrade test of 2026-11-14 in a systemd container. Run from a git clone
of v3.3.6, the upgrade passed: data unchanged and sessions kept. Run the documented way, it did
not.

| Upgrade Domain | Technical Implementation | Operational & Performance Benefit |
| :--- | :--- | :--- |
| **The Right Release** | Run from a copy without `.git`, `upgrade.sh` fetched a hard-coded older branch. It now fetches `EPHEMRES_BRANCH`, else its own release. It refuses a downgrade (`EPHEMRES_ALLOW_DOWNGRADE=1` to force one) and releases older than v3.3.6. | The documented command no longer reinstalls the old release. |
| **Each Release Upgrades Itself** | After fetching, the script hands over to the fetched release's own `upgrade.sh` when it differs. Until now, the installed script ran the new release with its own older steps, so a v3.3.5 script never installed `ephemres-snmpd`. From v3.3.5, run v3.3.6's script (deployment guide, section 3). | New steps of a release always run. |
| **Prepared Before Anything Stops** | The release is fetched, its frontend built and its Python packages downloaded and hash-checked before any service stops; on a netmon (v3.2 / v3.3.0) server a throwaway venv provides pip if the system Python has none. The packages are then installed without the network. | A failed download or build leaves the running version untouched. |
| **Services Back After a Failure** | The script records the services it stops. If it fails before the new code is copied in, it starts them again. After the migrations, it starts the new services. In between (new code, database not migrated), it says so and names the backup. | Until now, any failure left monitoring and alerting down until someone noticed. |
| **No /tmp** | The clone is staged in `/var/lib/ephemres` (`EPHEMRES_UPGRADE_STAGE_ROOT`), not `/tmp`. | Works on servers that mount `/tmp` noexec (CIS hardening), where the frontend build failed. |
| **One Version Number** | `backend/app/version.py` holds the release, read by the API, the PDF, alert footers, SSE and the upgrade script. The frontend takes `package.json`'s version through Vite. Install and uninstall banners read it or name none. | The UI, reports and API say 3.3.6; this branch still said 3.3.5 in about 20 places. |

## [Version 3.3.5] — Traffic Analytics, Per-Cycle Probe History, WAN Edge Totals & NetFlow Route Augmentation
### 🧭 NetFlow Route Discovery, WAN Perimeter Accounting, Sub-Cycle Probe Telemetry & Server-Side Conversation Forensics

| Upgrade Domain | Technical Implementation | Operational & Performance Benefit |
| :--- | :--- | :--- |
| **NetFlow Next-Hop Decoding & Path Observations (`0017`)** | Decoded IPv4/IPv6 forwarding next-hop addresses across NetFlow v5 (`nexthop`), NetFlow v9 (fields `15`/`62`), and IPFIX (IE `15`/`62`).
