# v3.4 Dashboard Data & Design Plan

Merged implementation plan for the Bandwidth (flow), Network Dashboard and Endpoint Detail
pages. It combines three reviews held on 2026-10-26: a data-quality review of what each page
collects and shows, an implementation review of what the fixes touch, and a UI design
critique run against a local build with synthetic data.

Every phase ships on its own version branch and must leave the backend suite green
(`.venv/bin/python -m pytest`) and `npm run build` clean.

## Guardrails

- **API changes are additive.** New fields are optional; existing fields keep their names for
  at least one release. When a value changes meaning (in/out stop absorbing transit traffic)
  the replacement field ships in the same release.
- **One source of flow math.** `app/services/flow_metrics.py` is shared by
  `routers/bandwidth.py` and `services/report_compiler.py`, so the dashboard and the PDF report
  cannot disagree.
- **Real-database tests for SQL and continuous-aggregate changes.** Tests marked `timescale`
  run against a throwaway TimescaleDB (`tests/integration/README.md`). The default suite skips
  them when no database is configured.
- **Characterization first.** The integration tests pin today's numbers, including known-wrong
  ones (the 50/50 transit split, the materialized-only lag). A phase that fixes one of them
  changes the matching assertion in the same commit and says why.
- **New tables are registered everywhere a backup needs them**: `core/restore.py` (table list
  and column-type map), `deploy/RESTORE.md`, and the retention service. Continuous aggregates
  built on a short-retention hypertable use a refresh `start_offset` shorter than that retention.
- **Design tokens only.** New or touched UI uses `var(--…)` tokens from `App.vue` and the
  primitives in `frontend/src/components/ui/`; no new hex values in views. Charts read colors
  through `useChartTheme()`.
- **Check both themes at 1280 px and 800 px** for every changed screen.
- **No new dependencies** (backend runtime stays `uvicorn` + `asyncpg`; frontend additions need
  sign-off).

## Phase 0 — Safety net (no behaviour change)

Code
- TimescaleDB integration harness (`tests/integration/`), with characterization tests for
  `/bandwidth/overview`, `/traffic-series`, `/top-talkers`, `/applications`, `/interfaces`.
- `app/services/flow_metrics.py`: rate, utilization, interface alias, DSCP bucketing, traffic
  zone and TCP anomaly helpers; `bandwidth.py` and `report_compiler.py` call it. Unit tests
  prove the helpers reproduce the previous inline results.

Design (D0)
- Chart, series and status tokens in `App.vue` (light and dark).
- `composables/useChartTheme.js`: chart colors from tokens, reactive to the `.dark` class.
- `utils/format.js` (bps, pps, bytes, numbers, speed, port labels) and `utils/statusTone.js`
  (uptime/utilization tone with one threshold set).
- Primitives in `components/ui/`: `SegmentedControl`, `TimeRangePicker`, `PanelHeader`,
  `KpiTile`. Built and documented, not yet wired into screens.

## Phase 1 — Correctness (honest numbers, honest UI)

Code
- Dashboard: fleet SLA and uptime sort stop treating 0 % as 100 % (`DashboardView`,
  `ReportsView`); passive/paused/unknown endpoints get their own KPI bucket and leave the SLA.
- Loss % shows "—" until Phase 2 supplies real loss; "Last Seen" becomes "In state since".
- Interfaces: `speed_configured` flag; utilization is `null` when speed is not configured.
- Flow series and overview: transit traffic reported as `transit_bps`/`transit_pps` instead of
  being split 50/50 into ingress/egress.
- Bandwidth KPIs follow scope and window (or are labelled "Fleet · last 5 min"); unregistered
  scope stops showing global data.
- Endpoint detail: charts fetch the whole range independently of table paging; correlated
  interface picker reads `name`; incident subtext matches what is counted.

Design (D1)
- Fix the app chips (`app.dst_port` → `app.port`) so labels and port filtering work.
- Neutral "Not monitored" presentation for passive exporters (no red 0 %).
- Area charts start at zero; state timeline uses real time labels.
- Light-mode status text contrast (pills and uptime text ≥ 4.5:1).
- 24 px minimum targets for row checkboxes and table icon actions.
- Rename jargon: "Burst Count" → "Flows", "Packet Physics" → "Avg packet size".
- Replace the toggles on every screen touched in this phase with the D0 primitives and
  `useChartTheme()` (fixes the light-mode chart text when the theme is toggled in place).

Found and fixed while doing Phase 1
- `GET /endpoints/{id}` dropped `device_role`, `flow_exporter_ips` and `flow_interface_aliases`,
  so the detail page never showed the passive-exporter banner, never opened exporters on the
  flow tab, and reported "No secondary exporter IPs linked" for every device.
- The detail page's 60 s poll reset the audit table to page 1 and switched flow exporters back
  to the flow tab every minute.
- `tests/integration/timescale.sh` reported ready during the image's first-time init restart.

Left for Phase 2: Reports still lists a full-period "UP duration" for passive exporters (it
comes from the uptime calculator, not the UI).

## Phase 2 — Data model

Code
- Migration 0014: `materialized_only = false` on `flow_hourly_rollups` and `flow_daily_rollups`
  (verified to work inside a transaction on TimescaleDB 2.27).
- Per-cycle probe storage: `PingResult` gains min/max/jitter; new `endpoint_probe_samples`
  hypertable written by the state machine each cycle, with compression, retention and an hourly
  aggregate. Feeds Loss %, 24 h average/p95 RTT, last probe time, RTT trend and the
  correlated view.
- `flow_interface_hourly_rollups` (sum + busiest minute) for windows beyond 7 days; p95 and peak
  utilization; rate divides by the time actually covered.
- Exporter health: last flow time and flows/s per exporter; unmatched exporters get
  `flow_count`.

Design (D2)
- Endpoint detail status header: state, current RTT and loss, time in state, last probe;
  monitoring/active toggles become labelled switches.
- RTT chart on a real time axis with min/max band and loss markers; correlated view as two
  charts sharing one time axis.
- Dashboard table sparklines; interface cards with p95/peak markers and a "Set speed" state.

Phase 2 decisions and notes
- Probe history retention (decided 2026-10-26): raw samples 30 days, hourly aggregate 365 days.
  Roughly 1.4 M rows/day per 1,000 endpoints, about 12 MB/day once compressed.
- Interface p95 counts idle minutes as zero; on the 30-day window it is over hourly averages
  (continuous aggregates cannot hold percentiles). Peaks are always the busiest minute.
- Found and fixed: without `CAP_NET_RAW` the raw ICMP tier reported every probe as lost instead
  of falling back to the unprivileged socket. Production units grant the capability; dev runs and
  containers that drop it now fall back (logged once).
- Restore rebuilds aggregates from restored source rows, so aggregate history older than the
  source retention is not restored (documented in `deploy/RESTORE.md`).

## Phase 3 — API & layout

Code
- Conversations filtered and paged on the server (`ip`, `port`, `dscp`, `anomaly`, `offset`);
  indexes only after `EXPLAIN` on realistic data.
- Top talkers from one `UNION ALL` + `GROUP BY ip`; application share against the total with
  an "Other" row; one anomaly definition shared by KPI and table; zones report resolution.

Design (D3)
- Bandwidth page becomes "Traffic Analytics" with Overview / Interfaces / Conversations / QoS /
  Security views (route `/bandwidth` kept).
- Dashboard: severity-first default sort, search and type/location filters persisted in the URL.
- Responsive header navigation below ~1000 px; Topology toolbar actions menu and collapsible
  legend; visually hidden text summaries for charts.

Phase 3 progress
- Done: `GET /bandwidth/conversations` (server filters, quick-filter counts over all matches,
  paging, sort); one-query top talkers; application shares of all traffic with an "Other" row;
  `zones_resolution`; one anomaly rule (`flow_metrics.tcp_anomaly_sql`, checked against the
  Python rule for all 256 flag masks) used by the overview KPI, the conversation table and the
  PDF report; Traffic Analytics page with Overview / Interfaces / Conversations / QoS / Security
  views kept in the URL; shared `ConversationsPanel` (also on Endpoint Detail); nav renamed
  "Traffic" with the `/bandwidth` route unchanged.
- Index measurement (2.0 M minute rows, 1,400 conversations, 24 h, TimescaleDB 2.27): the
  conversation query takes ~100 ms for 1 h and ~1.45 s for 24 h unfiltered (a full aggregation,
  no index helps). A 24 h IP filter takes 128 ms with a parallel sequential scan and 2 ms with
  indexes on `(src_ip, bucket DESC)` and `(dst_ip, bucket DESC)`, which add 121 MB to a 562 MB
  table (+21 %) and cost on every flow insert. Not added; decision pending.
- Still open in Phase 3: Dashboard severity-first sort, search and filters in the URL;
  responsive header navigation; Topology toolbar menu and legend; chart text summaries.

## Phase 4 — Decisions required first

- Fleet totals: count WAN-role interfaces only (needs an interface role in interface config).
- Spreading long flows across their duration using `ts_end` (ingest hot path; behind a setting).
- Retention and disk budget for per-cycle probe samples.
